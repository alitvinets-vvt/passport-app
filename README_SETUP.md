# Плановий Паспорт — скелет (крок 3)

Перевірено офлайн: парсер коректно розбирає файл
«Параметри_Паспорт_майстер.xlsx» на 7 блоків, включно з
незаповненими (жовтими) клітинками друку.

## Що зроблено
- `sheets_reader.py` — читає одну вкладку «Тарифи» (банерна структура),
  повертає структуровані параметри + список ще не заповнених значень.
- `app.py` — Streamlit: форма вводу з §2 драфту v0.2 + діагностична
  панель, яка показує, що реально підтягнулось із таблиці.
  Розрахунків собівартості й РРЦ тут немає — це крок 4.

## Що треба зробити тобі, щоб застосунок ожив

1. **Імпортувати `Параметри_Паспорт_майстер.xlsx` у Google Sheets**
   (Файл ▸ Імпорт ▸ Замінити таблицю або створити нову).

2. **Розшарити таблицю** на той самий service account, що вже
   використовує Vivat Calc (той самий `GOOGLE_SERVICE_ACCOUNT_JSON`) —
   права «Читач» достатньо.

3. **Скопіювати ID таблиці** з URL:
   `https://docs.google.com/spreadsheets/d/`**`<ОЦЕ>`**`/edit`

4. **Задати змінні середовища** (Railway Variables або локальний `.env`
   за зразком `.env.example`):
   - `PASSPORT_SHEET_ID` — ID з кроку 3
   - `GOOGLE_SERVICE_ACCOUNT_JSON` — той самий, що в Vivat Calc

5. **Локальний запуск (перевірка перед деплоєм):**
   ```
   pip install -r requirements.txt
   streamlit run app.py
   ```

6. **Деплой на Railway** — новий сервіс, підключений до GitHub-репо
   з цими файлами; Railway підхопить `requirements.txt` і `app.py`
   автоматично (той самий патерн, що Vivat Calc).

## Що має показати успішний запуск
- Панель «Діагностика читання параметрів» — 5 тарифів перекладу,
  3 редагування, 3 формати, 9 ефектів обкладинки, 5 тирів, 9 загальних.
- Попередження про ~16 незаповнених значень (ціна зошита ×3,
  зріз ×3, обкладинка ×9, множник 4+4 ×1) — це нормально, чекаємо
  на технолога.
- Форма вводу підтягує правильні числа під обрані зірковість/
  складність/формат/тир.

## ⚠️ Значення в блоках друку — ТЕСТОВІ, не фінальні ціни

У Google-таблиці «Параметри_Паспорт_майстер» станом на 2026-09-11
блоки ФОРМАТИ / КОЛЬОРОВИЙ ЗРІЗ / ОБКЛАДИНКА / множник 4+4 заповнені
**тестовими** контрольними числами, а не реальними цінами від
технолога:

- Ціна зошита T3 (усі 3 формати): **50**
- Ціна зрізу (усі 3 формати): **20**
- Обкладинка (формат × ефект): **50 / 60 / 70**
- Множник блоку 4+4: **2.0**

Ці числа зафіксовані навмисно як контрольний приклад для
`test_calculator.py` (700 000 знаків / простий / не перекладна /
84х108/32 / ч/б / Норма / без зрізу / наклад 3100 →
ОРИГІНАЛ-МАКЕТ=56 519,27, друк_за_шт=950, РРЦ=3779). **Не заміняй
їх на реальні ціни, поки не звірите разом і не оновите заразом
еталонні числа в тесті** — інакше автотест почне падати без
жодної реальної регресії в коді.
